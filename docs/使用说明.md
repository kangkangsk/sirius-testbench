# Sirius自动化测试工作台使用说明

## 启动

```bash
cd /Users/zhaomk/workspace/mycode/github/sirius-testbench
npm install
npm run dev
```

- 前端地址: `http://localhost:5175`
- 后端 API: `http://localhost:5174`
- 前端端口使用 `5175`，因为本机已有 `frpc` 占用 `127.0.0.1:5173`。

## 页面功能

| 页面 | 功能 |
| --- | --- |
| 工作空间 | 设置本地文件工作空间，查看 session/report 目录结构 |
| 抓包会话 | 启动有界面 Chromium，实时分开展示 HTTP 请求和静态资源 |
| 请求整理 | 分开展示 HTTP 请求和静态资源页面；只对 HTTP 请求做启用、禁用、删除和回放 |
| 登录态替换 | 保存统一 Cookie、Header、目标 IP/端口、URL/Body 替换规则 |
| 回放测试 | 按抓包顺序逐个执行 enabled 请求，实时展示请求状态和总体进展，支持登录接口 Cookie 接续，生成 `reports/*/result.json` |
| 脚本导出 | 生成 `scripts/replay-raw.sh` 或 `scripts/replay-with-auth.sh` |

## 抓包方式

点击“开始抓包”后，后端用 Playwright 启动有界面 Chromium。用户在浏览器中登录和操作，服务端监听页面网络事件:

如果 URL 未填写协议，前端和后端会自动补齐协议: `localhost` / `127.0.0.1` 默认使用 `http://`，其他域名默认使用 `https://`。浏览器启动成功后接口会立即返回，目标站点加载慢或失败不会让“开始抓包”按钮长时间无反馈。

抓包结果按用途拆成两个清单:

- `requests.json`: 业务 HTTP 请求，包含 `xhr`、`fetch`、非静态扩展名等后续需要整理、回放、导出脚本的请求。
- `resources.json`: 静态资源请求，包含 `document`、`stylesheet`、`script`、`image`、`media`、`font`、`manifest`，以及 `.js`、`.css`、`.html`、图片、字体等静态文件扩展名。

`capture.json` 保留合并视图，包含 `requests`、`resources` 和按抓包顺序排序的 `traffic`。

### 抓包中后端闪退修复说明

早期版本在抓包事件和前端状态轮询同时写入 `requests.json` 时，多个写操作会共用同一个 `requests.json.tmp` 临时文件，可能触发 `ENOENT rename ... requests.json.tmp` 并导致后端退出。当前版本已改为:

- 每次写 JSON 使用唯一临时文件名。
- 同一个 session 的快照写入按队列串行执行。
- 写失败时自动清理本次临时文件。

```js
page.on('request', async (request) => {
  saveRequest({
    method: request.method(),
    url: request.url(),
    resourceType: request.resourceType(),
    trafficType: classifyTraffic(request),
    headers: request.headers(),
    postData: request.postData(),
  });
});
```

```js
page.on('response', async (response) => {
  saveResponse({
    status: response.status(),
    headers: response.headers(),
    body: await safeReadBody(response),
  });
});
```

## 文件结构

```text
workspace/
  sessions/
    {sessionId}/
      meta.json
      requests.json
      resources.json
      capture.json
      capture.har
      auth.override.json
      scripts/
      reports/
```

原始认证信息不会脱敏，也不会在抓包阶段被替换。`auth.override.json` 只在回放测试和脚本生成阶段生效。

请求整理页修改启用状态时，如果抓包会话仍在运行，会同步更新服务端内存中的抓包快照，避免后续刷新或停止抓包时旧内存数据覆盖 `requests.json`。

## 回放登录态规则

- 如果请求整理页将某个 enabled 请求分类为“登录”，回放时会从该登录响应的 `Set-Cookie` 提取 Cookie，并注入后续每个请求。
- 如果没有启用的登录接口，回放页默认使用“统一替换”模式，读取登录态替换页保存的 Cookie。
- 登录态替换页可同时配置目标协议、IP/域名、端口，回放时只替换 URL 的 origin，路径和查询参数保持不变。
